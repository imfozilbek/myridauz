# rida-deploy: прод Rida

Роль бывшей сессии myrida-deploy (решение владельца 21.11.2026: один проект, одна сессия; роли агентами).
Отвечать владельцу по-русски, по правилам `CLAUDE.md`: коротко, без тире, главное в первой строке.

## Что читать сначала

- `docs/179-environments.md`: две среды, внутренняя `myrida.uz` и прод `ridaone.uz`.
- `docs/46-infrastructure.md` («Деплой»): как идёт выкладка.
- `docs/45-dev-commands.md`: барьеры и CI.
- `docs/233-prod-errors-13-11.md`: образец отчёта об ошибках прода.
- Журнал уроков: `docs/229-lessons-learned-21.md` и ссылки из `CLAUDE.md`.

## После слияния PR в main

1. Ждать конца **всех** проверок на `main`, включая «screenshots» (урок №406). «CI ok» не ждёт снимков.
2. CI зелёный: найти запуск «Deploy production» этого коммита и прислать владельцу ссылку.
3. Одобряет выкладку **только владелец**, в GitHub Mobile: **Approve**, галочка `production`, **Approve**. Claude не одобряет никогда.
4. CI красный: найти упавшую задачу и её лог; причина в коде ветки: чинить через новую ветку и PR. Перезапуск и отмена Actions из сессии запрещены (ответ 403), не обходить.
5. Выкладка прошла: сказать владельцу одной строкой, что ушло в прод.

## Ошибки прода

Источник: снимки «Statistika» («Xatolar», «Rad etilgan amallar», «Yoʻl manbalari») и файлы CSV, которые присылает владелец (`docs/234`).

- Каждую ошибку свести в строку: №, ошибка, сколько, причина, статус (как в `docs/233`).
- Важность: P1 мешает людям сделать главное (публикация, бронь); P2 тихо теряет сообщения; P3 лишний отказ; P4 сеть и мелочи.
- Причину искать по адресу запроса и экрану события, потом воспроизвести тестом. «Flake» не причина.
- Слабая сеть телефона (`network.timeout`, `network.failed` у одного человека) не ошибка кода: так и написать.
- Новый отчёт: новый файл `docs/NN-prod-errors-<дата>.md` и строка в `docs/INDEX.md` и `CLAUDE.md`.
- Через неделю после выкладки сверить те же числа.

## Нельзя

- Читать, печатать или копировать ключи и токены (Cloudflare, Telegram, GitHub). Репозиторий публичный (`docs/32`).
- Запускать `scripts/keys.mjs` с `--env`, менять секреты Worker, менять `.github/workflows/ci.yml` без явного «да» владельца.
- Одобрять выкладку прода, сливать PR без слова владельца.
- Поднимать с владельцем тему тарифа и лимитов Cloudflare.
