# Rida: правила для Claude

Rida: сервис **совместных поездок с разделением расходов** (carpooling)
по Узбекистану (`myrida.uz`). **Rida не такси.** Никаких «заказов» и
«тарифов»: только «поездка», «место», «доля расходов» (`docs/01-project-overview.md`).
**Главный принцип: держать людей в Rida максимально** (`docs/18-retention.md`).
**Код: white-label:** на нём можно запустить второй бренд. Имя, домен, цвета,
боты, модель монетизации: только в `brands/<brand>/`, никогда в коде
(`docs/22-multi-brand.md`).
**Продукт только на узбекском языке (латиница)**: все тексты в ботах,
Mini App, каналах, уведомлениях и лендинге. Код: на английском.
Узбекские тексты: только по `docs/25-uzbek-language-guide.md` (источники,
орфография oʻ/gʻ, стиль, глоссарий); каждый текст проверяет носитель.
Архитектура готова к мультиязычности: **никакого текста в коде, только ключи
перевода** (`docs/13-i18n.md`).

Вся информация о проекте: в папке `docs/`. Начинать с `docs/INDEX.md`.

## Запрет длинных тире (решение владельца)

- **Никогда не использовать длинное тире «—» и среднее «–»** в этом проекте:
  тексты продукта, переводы, документы, комментарии, мои ответы.
- Лучше всего **обходиться без тире вообще**, даже без дефиса «-» в роли тире.
  Перестроить фразу: двоеточие, запятая, точка, скобки или другой порядок слов.

## Язык и стиль ответов

- Отвечать пользователю **только на русском языке**.
- Ответы должны быть внятными, чёткими и по делу. Без воды.
- Писать так, чтобы понял человек, для которого русский **не родной язык**:
  - короткие предложения, одна мысль в одном предложении;
  - простые, частые слова; без идиом, сленга и сложных оборотов;
  - технический термин с коротким пояснением при первом упоминании.
- Каждый ответ проходит через призму **cognitive ease** (когнитивная лёгкость):
  - главное в первой строке;
  - структура: заголовки, списки, таблицы вместо длинных абзацев;
  - минимум вариантов: одна рекомендация, а не список из всех возможных;
  - понятный следующий шаг в конце, если он нужен.

## Правила документации

- **Любая тема обсуждения с владельцем** фиксируется в документе в `docs/`.
- Имя файла: `NN-тема-на-английском.md`: номер по порядку (01, 02, …)
  и понятное название в kebab-case. Заголовок файла: `# NN. Тема`.
- **Лимит: 150 строк на файл.** Если файл больше: разбить тему на две
  отдельные подтемы (два файла со своими номерами).
- Новая тема: новый файл со следующим свободным номером.
  Уточнение старой темы: правка существующего файла.
- **`docs/INDEX.md`**: индекс всех документов. Обновлять при каждом
  добавлении, переименовании или разбиении файла.
- Нерешённые вопросы: в `docs/10-open-questions.md`. Когда вопрос решён,
  решение переносится в профильный документ.
- Этот файл (`CLAUDE.md`) тоже должен знать, где что лежит: карта ниже.

## Правила кода (подробно: `docs/11-code-architecture.md`)

- **Максимум 150 строк на любой файл кода.** Больше: разбить на части.
- **Общее: выносить** в `shared/` или `packages/`. Без дублирования.
- Backend: модульный монолит (слои `domain` / `application` /
  `infrastructure` / `http`). Frontend: Feature-Sliced Design.
- Один файл = одна ответственность. TypeScript `strict`, без `any`.
- **Чистый код и чистая архитектура**: бизнес-логика не зависит от
  фреймворков и базы; понятные имена; маленькие функции; без магических
  чисел, дублирования и мёртвого кода. Цель: код легко поддерживать годами.

## Правила интерфейса (подробно: `docs/19-design-system-and-ux.md`)

- Иконки и стили: **только из готовых библиотек** (TelegramUI + Lucide),
  через обёртку `packages/ui`.
- Интерфейс **максимально простой**: человек без опыта в IT сразу находит
  нужное. Один экран: одно действие; выбирать, а не печатать;
  иконка всегда с подписью.
- **Бренд:** белый + бирюзовый + янтарный, только токены из `packages/ui`.
  **Только светлая тема, тёмной нет никогда** (`docs/20-brand.md`).
- **Ощущение родного Telegram:** человек не выходит из Telegram; только
  родные элементы Telegram SDK; отличие: только цвета (`docs/21-native-feel.md`).
