# Rida: правила для Claude

Rida: сервис **совместных поездок с разделением расходов** (carpooling)
по Узбекистану (`myrida.uz`). **Rida не такси.** Никаких «заказов» и
«тарифов»: только «поездка», «место», «доля расходов» (`docs/01-project-overview.md`).
**Главные принципы: Rida сделан для людей, строим вокруг людей и общества** (`docs/01`); **держать людей в Rida максимально** (`docs/18-retention.md`).
**Код: white-label:** на нём можно запустить второй бренд. Имя, домен, цвета,
боты, модель монетизации: только в `brands/<brand>/`, никогда в коде
(`docs/22-multi-brand.md`).
**Продукт только на узбекском языке (латиница)**: все тексты в ботах,
Mini App, каналах, уведомлениях и лендинге. Код: на английском.
Узбекские тексты: только по `docs/25-uzbek-language-guide.md` (источники,
орфография oʻ/gʻ, стиль, глоссарий); каждый текст проверяет носитель.
Архитектура готова к мультиязычности: **никакого текста в коде, только ключи перевода** (`docs/13-i18n.md`).

Вся информация о проекте: в папке `docs/`. Начинать с `docs/INDEX.md`.

## Запрет длинных тире (решение владельца)

- **Никогда не использовать длинное тире «—» и среднее «–»** в этом проекте: тексты продукта, переводы, документы, комментарии, мои ответы.
- Лучше всего **обходиться без тире вообще**, даже без дефиса «-» в роли тире. Перестроить фразу: двоеточие, запятая, точка, скобки или другой порядок слов.

## Цель: запуск 1 февраля 2027 (решение владельца)

- План и объём запуска: `docs/27-launch-roadmap.md`.
- **Если просьба владельца отдаляет от запуска**, Claude прямо говорит:
  «Это может отдалить запуск, потому что осталось X, а мы делаем Y».
  Решает владелец. Сказать об этом обязательно.

## Цели (решение владельца)

- Путь к продукту разбит на цели: `docs/goals/INDEX.md` (G01 … G20, OPS для владельца).
- Владелец пишет «дай следующую цель»: Claude присылает одну цель одним блоком кода (копируется одной кнопкой). Владелец отдаёт текст цели. Claude выполняет её **до конца**: не останавливается, пока все пункты Definition of Done не выполнены.
- После цели: обновить статус в `docs/goals/INDEX.md` и профильные docs.
- **Согласие владельца** (`docs/33-owner-approvals.md`): прод, необратимое, публичное, деньги, юр. документы, тексты, вид экранов, расходы.
  Спросить одним сообщением, пока ждём, делать то, что от ответа не зависит.
- **Каждую выполненную задачу показывать скриншотами** (`docs/33`).
- **Одна цель = одна ветка** `goal/gNN-...`. Цель закрыта, когда ветка слита в `main` без конфликтов и в `main` всё работает (`docs/34`). После слияния ненужные ветки удаляются сразу.

## Причины и следствия (решение владельца)

- Каждая ошибка записывается в `docs/26-lessons-learned.md` (продолжение `docs/44`, `docs/49`, `docs/66`, `docs/84`, `docs/91`, `docs/99`, `docs/113`): что случилось,
  причина, следствие, урок. Урок становится правилом.
- **Перед каждым решением** проверять журнал уроков. Если предложение
  повторяет старую ошибку, сразу сказать: «Это похоже на урок №N».

## Язык и стиль ответов

- Отвечать пользователю **только на русском языке**. Внятно, чётко, по делу, без воды.
- Писать так, чтобы понял человек, для которого русский **не родной язык**:
  - короткие предложения, одна мысль в одном предложении;
  - простые, частые слова; без идиом, сленга и сложных оборотов;
  - технический термин с коротким пояснением при первом упоминании.
- Каждый ответ проходит через призму **cognitive ease** (когнитивная лёгкость):
  - главное в первой строке;
  - структура: заголовки, списки, таблицы вместо длинных абзацев;
  - минимум вариантов: одна рекомендация, а не список из всех возможных;
  - понятный следующий шаг в конце, если он нужен.

## Правила документации (подробно: `docs/28-documentation-rules.md`)

- Любая тема обсуждения фиксируется в `docs/NN-тема.md`, индекс в `docs/INDEX.md`.
- Не больше 150 строк на файл, иначе разбить на подтемы. Cognitive ease: блок «Кратко» сверху, списки и таблицы.
- Clean Docs: одна тема в одном документе, один источник правды, без устаревшего.

## Правила кода (подробно: `docs/11-code-architecture.md`)

- **Максимум 150 строк на любой файл кода.** Больше: разбить на части.
- **Общее: выносить** в `shared/` или `packages/`. Без дублирования.
- Backend: модульный монолит (слои `domain` / `application` /
  `infrastructure` / `http`). Frontend: Feature-Sliced Design.
- Один файл = одна ответственность. TypeScript `strict`, без `any`.
- **Чистый код и чистая архитектура**: бизнес-логика не зависит от
  фреймворков и базы; понятные имена; маленькие функции; без магических
  чисел и дублирования. Цель: код легко поддерживать годами.
- **Ни одной неиспользуемой строки кода:** ни файлов, ни функций, ни импортов,
  ни зависимостей, ни закомментированного кода, ни кода «на будущее».
  Проверяют `tsc` (`noUnused*`), ESLint и `knip` в CI.
- **Всё закрыто тестами**, барьеры CI не пускают ошибки в прод (`docs/31`).
- **Репозиторий публичный:** секретов в коде и в CI для PR нет никогда (`docs/32`).

## Правила интерфейса (подробно: `docs/19-design-system-and-ux.md`)

- Иконки и стили: **только из готовых библиотек** (TelegramUI + Lucide),
  через обёртку `packages/ui`. Исключение: MapLibre только на экране карты (`docs/67`).
- Интерфейс **максимально простой**: человек без опыта в IT сразу находит
  нужное. Один экран: одно действие; выбирать, а не печатать;
  иконка всегда с подписью.
- **Бренд:** белый + бирюзовый + янтарный, у каждой Mini App свой главный цвет (`docs/20`), только токены.
  **Только светлая тема, тёмной нет никогда** (`docs/20-brand.md`).
- **Ощущение родного Telegram:** человек не выходит из Telegram; только
  родные элементы Telegram SDK; отличие: только цвета (`docs/21-native-feel.md`).
  Планка: минимализм, понятно любому, уровень продуктов на миллиард (`docs/21`).
- **Ничего не исчезает и не обрезается** (решение владельца): на узком экране всё уменьшается; одинаковые элементы одного размера; плитки квадратные, широкие одной высоты (`docs/121`).
- **Маршрут везде «район, область, место, ориентир»**, без сокращений (`docs/121`).
