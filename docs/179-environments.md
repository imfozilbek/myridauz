# 179. Две среды: внутренняя и прод

> **Кратко:** решение владельца 13.10.2026. Первый аккаунт Cloudflare и `myrida.uz` становятся **внутренней средой** команды. Новый аккаунт и `ridaone.uz`: **прод** для людей. Код один, бренд один. Отличаются адрес, боты и каналы. Цель G81.

## Решение владельца (13.10.2026)

- «Текущая среда стала внутренней для использования»; новый аккаунт Cloudflare, на нём весь стек.
- Внутренняя: 2 канала. Главный, как сейчас, и один для всех направлений: туда идут поездки.
- Прод: 67 каналов направлений и один главный канал (`176`).
- Адрес прода `ridaone.uz`, боты прода `@rida1uz_*` (владелец через сессию инфраструктуры).

## Как устроено в коде

- `brands/rida/environments.ts`: имя, адрес, `indexed`, боты, каналы и главный канал каждой среды.
  Остальное в `brand.config.ts`, одно на обе (`22`).
- `loadBrand(id, environment)`: без среды прод. Тесты и стенд работают с продом (67 каналов).
- Worker читает переменную `ENVIRONMENT`, Mini App, их заставка при сборке и сайт: `VITE_ENVIRONMENT`.
- Команды `deploy`, `setup-bots`, `map-data` требуют `--env=internal|production`.
  Прод «по умолчанию» никогда. Стенд (`--local`) среду не спрашивает.
- `brands/rida/wrangler.toml` один. Деплой пишет `wrangler.<среда>.toml` (git его не хранит):
  адрес API, id базы D1 этого аккаунта, `ENVIRONMENT`.
- На пустом аккаунте деплой сам создаёт D1 `rida-db`, очередь `rida-notifications`, R2 `rida-media`.
  Карту `rida-map`, проекты Pages и их домены он создавал и раньше (`46`).
- Имена `*.pages.dev` общие на весь Cloudflare: проект второго аккаунта получает адрес с окончанием (`rida-landing-xxx.pages.dev`). Запись DNS ведёт на адрес из самого проекта, неверную деплой исправляет (урок №306).
- Имена ресурсов одинаковые в обоих аккаунтах. Отличается только id базы D1.
- Деплой и «Map data» сначала ищут на аккаунте секретов зону домена своей среды (`scripts/deploy/account.mjs`).
  Зоны нет: это секреты другой среды, команда останавливается до любых изменений (урок №271).
- Канал «MyRida | Viloyatlar» в коде с 17.10.2026 (G84): все места всех направлений, поэтому поездка из любого места идёт туда. Аватар: области `10`, своей картинки нет.
  До этого у внутренней среды каналов направлений нет: посты никуда не идут.

## Ключи обеих сред (карта владельца 15.10.2026)

Все ключи и настройки обеих сред делает программа `pnpm run keys` (решение владельца 17.10.2026); шаги и наборы прав: `189`. Карта ключей infra (`dream-infra`, `docs/18-rida-keys.md`) повторяет эту таблицу.
Правило: один ключ лежит в одном месте и делает одно дело; имя `rida-<среда>-<задача>`. Обе среды симметричны: те же наборы прав, имена и настройки.

| Ключ | Аккаунт | Права | Где лежит, имя |
|---|---|---|---|
| ключ шаблона «Create Additional Tokens» | первый | только создаёт другие ключи; до конца G84 | окружение Claude: `CLOUDFLARE_API_TOKEN` |
| `rida-internal-deploy` | первый | набор «Выкладка», зона `myrida.uz` | GitHub Environment `internal`: `CLOUDFLARE_API_TOKEN` |
| `rida-internal-analytics` | первый | только Account Analytics: Read | секрет Worker: `ANALYTICS_API_TOKEN` |
| ключ шаблона «Create Additional Tokens» | новый | только создаёт другие ключи; до конца G84 | окружение Claude: `PROD_CLOUDFLARE_API_TOKEN` |
| `rida-prod-deploy` | новый | набор «Выкладка», зона `ridaone.uz` | GitHub Environment `production`: `CLOUDFLARE_API_TOKEN` |
| `rida-prod-analytics` | новый | только Account Analytics: Read | секрет Worker прода: `ANALYTICS_API_TOKEN` |

- Рядом с ключом: Account ID своего аккаунта (`CLOUDFLARE_ACCOUNT_ID`, `PROD_CLOUDFLARE_ACCOUNT_ID`, в Worker `CF_ACCOUNT_ID`).
- Окружение Claude для Rida: только эти 4 переменные. Токенов ботов в нём нет: окружение одно на все проекты. Новые значения видит только новая сессия.
- Старые токены (`rida-deploy`, `rida-claude`, `rida-*-claude`) удаляет `pnpm run keys --finish --yes` последним шагом: сначала новый `ANALYTICS_API_TOKEN` в Worker, без него статистика админки встанет (`117`).
- Токены 6 ботов своей среды кладёт владелец в секреты Worker. Cron сам ставит ботам вебхук, меню и описания (`46`).
- Значения ключей в чат и в репозиторий никогда (`32`).
- `deploy-internal`: без согласия, после зелёного CI на `main`. Прод (G84): workflow «Deploy production» после зелёного CI на `main` (выкладка внутренней прошла или ей нечего выкладывать), Environment `production` с **Approve** владельца (`32`). «Map data»: обе среды.
- На новом аккаунте до первой выкладки владелец один раз включает в панели R2 и Analytics Engine (урок №303).
- Новая база D1 на пустом аккаунте: в Западной Европе, как у первого (`46`).

## Права ключа выкладки

Значение секрета в GitHub прочитать нельзя: «тот же токен, что в другом Environment» не скопировать (урок №297). Набор «Выкладка» в коде (`scripts/keys/rights.mjs`) и в `189`.

- Только то, что вызывает `scripts/deploy.mjs`: Worker и его маршрут, D1, очередь, R2, Pages, DNS. KV, Realtime и аналитика выкладке не нужны.
- Без «Workers Routes» выкладка падает после загрузки Worker: Mini App и сайт не выкладываются (15.10.2026).
- В GitHub ключ лежит в **Secrets** Environment, не в Variables. Секрет Environment сильнее секрета репозитория с тем же именем: общий секрет репозитория лишний.
