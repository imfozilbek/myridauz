# 66. Уроки: продолжение журнала (№39 и дальше)

> **Кратко:** Уроки №39 и дальше. `49` заполнен до лимита 150 строк. Правила журнала и короткая таблица всех уроков: `26-lessons-learned.md`.

### №39. Удалённый аккаунт снова получал бонус

- **Что случилось:** в G20 тест закрытия кошелька показал: человек удалил аккаунт, вернулся, владелец добавил деньги, и после первой поездки пришёл бонус 2 на 500 000 сум.
- **Причина:** правило бонуса считало бонус «потраченным», когда остаток 0, и не отличало закрытый бонус от потраченного.
- **Следствие:** в прод не ушло. Исправлено: закрытый бонус не открывает следующий.
- **Урок:** новое действие с деньгами проверяется вместе со всеми правилами акции: тест «вернулся и поехал снова».

### №40. e2e упал из-за двух одинаковых слов на экране

- **Что случилось:** в G21 проверка скриншотов в CI нашла два элемента с текстом «Hisobni toʻldirish»: заголовок и подсказку «Hozircha hisobni toʻldirish ishlamaydi». Локально тест прошёл.
- **Причина:** `getByText` ищет часть текста без учёта регистра. Локально подсказка появлялась позже проверки.
- **Следствие:** красный CI на PR #61, лишний круг. В прод не ушло.
- **Урок:** если те же слова могут быть на экране ещё где-то, искать с `exact: true`.

### №41. Три ответа владельцу на английском

- **Что случилось:** после технических уведомлений (CI, слияние) Claude ответил владельцу на английском. Владелец напомнил правило.
- **Причина:** уведомления приходят на английском, и ответ продолжил их язык.
- **Следствие:** владельцу, для которого важен русский, было труднее читать.
- **Урок:** любой ответ владельцу только на русском, в том числе сразу после уведомления.

### №42. Узбекское слово с именем бренда внутри

- **Что случилось:** в G22 тексты «tashqarida» и «sozlamalarida» не прошли `check:text`: внутри слова есть имя бренда.
- **Причина:** проверка ищет имя бренда как часть слова, чтобы не пропустить его в коде.
- **Следствие:** нашли до коммита, тексты переписаны («Oʻzbekistonda emas», «Telegramda»).
- **Урок:** новый текст сразу прогонять через `pnpm check:text`, до показа владельцу.

### №43. Карта не рисовалась, хотя unit-тесты были зелёные

- **Что случилось:** в G22 e2e показал две ошибки, которых unit-тесты не видят: MapLibre не нашла свой Worker (фоновый поток), и её CSS сделал коробку карты высотой 0.
- **Причина:** unit-тесты идут на подделке карты: jsdom не рисует WebGL. Библиотека приносит свой файл Worker и свой CSS.
- **Следствие:** нашли до PR. Исправлено: адрес Worker задан явно, правило CSS с двумя классами.
- **Урок:** экран с чужой библиотекой всегда проверять e2e в настоящем браузере и смотреть скриншот.

### №44. Первая загрузка карты упала на сбое чужого сервера

- **Что случилось:** workflow «Map data» упал на 99% скачивания: сервер сборок Protomaps ответил `HTTP 500`.
- **Причина:** у себя я видел такие сбои (524) и просто запускал скачивание снова. В скрипт этот повтор не попал.
- **Следствие:** владелец потратил запуск и время. Карта не попала в R2, в проде ничего не сломалось.
- **Второй запуск:** все 3 попытки снова упали около 97%. Мелкие запросы тоже не помогли: сервер сборок обрывает скачивание. Копия той же сборки на Source Cooperative отдала всё за 44 секунды.
- **Урок:** если шаг пришлось повторять вручную из-за внешнего сервиса, повтор встраивается в скрипт. Если сервис падает снова и снова, повторы не лечат: найти надёжный источник тех же данных и проверить его до запуска владельцем.

### №45. Карта скачалась, но R2 не принял файл

- **Что случилось:** третий запуск «Map data» скачал карту за минуту, но запись в R2 ответила `403 Authentication error`.
- **Причина:** ключу деплоя в GitHub раньше не нужно было писать файлы в R2. Права «Workers R2 Storage: Edit» у него нет. Я не сверил права ключа с новым действием.
- **Следствие:** ещё один запуск владельца впустую. В проде ничего не сломалось.
- **Урок:** новое действие в CI (запись в R2, новый сервис) сначала сверить с правами ключа в `32` и попросить владельца добавить право до запуска.

### №46. Поиск брал первые найденные места, а не ближайшие

- **Что случилось:** в G23 первый вариант поиска брал из D1 50 любых совпадений и сортировал их сам. Проверка на полном индексе: «maktab» рядом с Ташкентом даёт 647 школ, и ближайших среди 50 могло не быть.
- **Причина:** unit тесты шли на 3 или 12 местах, где все совпадения помещаются в 50.
- **Следствие:** нашли до PR. Исправлено: D1 сама сортирует по расстоянию и отдаёт 10 ближайших.
- **Урок:** поиск и сортировку проверять на полном объёме настоящих данных, самый частый запрос тоже.

### №47. PR слили раньше, чем в него попали последние коммиты

- **Что случилось:** PR #68 (документы 70 … 73) владелец слил, пока я ещё отправлял в ветку коммиты. В `main` не попали docs 70 … 73, CLAUDE.md и INDEX.
- **Причина:** я попросил слить PR до того, как закончил ветку, и не сверил последний коммит PR с концом ветки.
- **Следствие:** в начале G24 документы пришлось переносить из старой ветки. Потерь нет.
- **Урок:** просить слияние только когда ветка закончена; в просьбе писать последний коммит PR, после слияния сверять `main` с веткой.

### №48. Карту нельзя было сдвинуть в другой район, кнопку закрывала главная кнопка

- **Что случилось:** в G24 e2e нашёл две ошибки экрана «Qayerdan / Qayerga», которых нет в unit-тестах: карта точки обрезана границей района, и поиск места в другом районе не мог её туда сдвинуть; кнопка «Roʻyxatdan tanlash» стояла внизу, под главной кнопкой Telegram.
- **Причина:** unit-тесты идут на подделке карты: у неё нет ограничения границ и нет главной кнопки.
- **Следствие:** нашли до PR. Исправлено: поиск снимает обрезку до перехода, далёкий переход без полёта, кнопка списка сверху; добавлен unit-тест на порядок «снять обрезку, сдвинуть».
- **Урок:** низ экрана с картой занят главной кнопкой Telegram, свои кнопки только сверху. Переход между районами проверять e2e в настоящем браузере.

### №49. SQL хранилища проверяется на настоящей SQLite

- **Что случилось:** в G24 история пятаков из D1 отдавала поля не в тех местах. Тест на памяти (подделке хранилища) это не видел.
- **Причина:** подделка хранилища повторяла логику, а не SQL.
- **Следствие:** нашёл новый тест на SQLite со всеми миграциями (`test-d1.ts`) до PR.
- **Урок:** у каждого хранилища D1 есть тест на SQLite со всеми миграциями, не только на подделке.

### №50. Граница старого района приходила поздно и тянула карту назад

- **Что случилось:** в G25 полный e2e под нагрузкой иногда падал: после поиска места в другом районе под булавкой оставался старый район.
- **Причина:** граница района загружается с сервера. Если она приходила уже после перехода к найденному месту, карта обрезалась по старому району и возвращалась туда.
- **Следствие:** нашли до PR. Исправлено: опоздавшая граница не применяется; unit-тест падал без исправления и проходит с ним.
- **Урок:** ответ сервера, который пришёл после того, как человек ушёл дальше, проверять на свежесть. Сбой e2e под нагрузкой искать в коде, а не списывать на случайность.

### №51. Главная кнопка на один кадр брала старое действие

- **Что случилось:** в G25 главную кнопку переделали, чтобы она не мигала при каждом обновлении экрана. После этого unit-тест поиска падал примерно в 1 случае из 4: поиск уходил со старым способом посадки.
- **Причина:** новое действие кнопки записывалось после отрисовки, в обычном эффекте. Нажатие, пришедшее между отрисовкой и эффектом, запускало прошлое действие.
- **Следствие:** нашли до PR. Исправлено: действие записывается сразу после отрисовки, до любого нажатия (`useLayoutEffect`); 12 запусков подряд зелёные.
- **Урок:** если тест иногда падает только после правки, сначала гонять его на коде без правки. 0 из 12 на старом коде значит, что причина в правке.
