# 47. Пользователи, вход и регистрация

> **Кратко:** Входа по паролю нет. Каждый запрос Mini App несёт подпись Telegram (initData) своего бота, сервер её проверяет. Первый вход: согласие, имя, пол, телефон из Telegram. Фото лежит в приватном R2 и видно только по правилам `05`. Сделано в G04 (28.09.2026).

## Вход (сессия)

- Mini App шлёт в каждом запросе два заголовка:
  `authorization: tma <initData>` и `x-mini-app: passenger | driver | admin`.
- Сервер проверяет подпись **токеном бота этого Mini App**
  (`apps/backend/src/shared/auth`). Подпись чужого бота не проходит.
- initData старше 24 часов не принимается (`auth.expired`),
  подделка: `auth.invalid`. Cookie и паролей нет.
- Админ Mini App: только Telegram ID из секрета `ADMIN_TELEGRAM_IDS`
  (`46`), иначе `auth.not_admin`.

## Пользователь

- Одна запись на человека для всех ботов (`02`), id = Telegram ID (только внутри сервера).
- Наружу человек виден по **публичному id**: 32 случайных символа (`public_id`, миграция `0020`).
  Все ответы API, адреса и ссылки из ботов несут только его. Новый аккаунт получает новый (G20, `65` A3).
- Поля: имя, пол, телефон, язык `uz-Latn`, согласие (время),
  блокировка, ключ фото, разрешение боту писать.
- Роли: пассажир у всех; водитель после модерации (G06);
  админ по списку команды.
- Таблицы D1: `users`, `blocked_phones` (`migrations/0002_users.sql`).

## Первый вход (пассажир и водитель)

Два экрана (G34, решение владельца 02.10.2026; было 5):

| Шаг | Экран | Что делает человек |
|---|---|---|
| 1 | Приветствие и согласие: логотип R, польза с иконками, строка согласия со ссылками на 3 документа | «Davom etish» значит согласие |
| 2 | «Siz haqingizda»: имя из Telegram (можно поправить), пол двумя строками с иконками (`06`), «Raqamingiz hech kimga koʻrinmaydi» | «Raqamni yuborish»: окно Telegram «Поделиться номером» |

- Логотип: `brands/<brand>/public/logo.svg` из бренд-пакета; у нового бренда свой файл (`22`).

- Телефон: только из Telegram (`requestContact`). Ответ подписан ботом,
  сервер проверяет подпись и что номер **свой** (`users.invalid_contact`).
- Имя: только буквы, 2 … 32 символа. Цифры и `@` запрещены:
  в имени нельзя спрятать контакт (`07`).
- После регистрации Mini App один раз просит Telegram разрешить боту
  писать (`requestWriteAccess`, `15`). Ответ сохраняется в профиле.
- Аналитика: событие `registration_step` (`29`): `consent` (приветствие), `about` (нажата «Raqamni yuborish»), `phone`, `done`. Разница `about` и `phone`: сколько людей не дали номер.

## Блокировка (`17`)

- По Telegram ID и по номеру телефона. Временная кончается сама.
- Заблокированный видит только экран «Hisobingiz bloklangan»
  (с датой окончания или без). Все запросы API: `403 users.blocked`.
- Боты на `/start` отвечают «Hisobingiz bloklangan.».
- Блокировать будет модератор в G11; таблицы и проверки уже готовы.

## Профиль

- Первая строка главного экрана: своё фото и имя, как в настройках Telegram.
- Экран профиля: фото, имя, рейтинг («Yangi», пока нет оценок, G11),
  свой телефон с подписью «видите только вы».
- Другим людям API отдаёт только: публичный id, имя, есть ли фото, рейтинг.
  Телефона и username в ответах о других **нет** (есть тест).

## Фото (аватар)

- Сжатие на телефоне: квадрат из середины, до 800 px, JPEG ~200 КБ.
  Сервер принимает до 320 КБ.
- Хранение: приватный R2 `rida-media`, ключ `avatars/<id>/<uuid>`.
  Публичной ссылки нет, фото отдаёт API после проверки прав.
- Кто видит (`05`): сам человек, модераторы, все видят фото водителя;
  фото пассажира видят только попутчики той же поездки с подтверждённой
  бронью. **Водитель фото пассажира не видит никогда.**
- Фото лица обязательно для обеих ролей (G58, `118`). Настройки
  `PASSENGER_AVATAR_REQUIRED` больше нет.
- Проверка фото (G58, часть G51): каждое новое фото ждёт команду
  (`avatarStatus`: `pending`, `approved`, `rejected`). Пока фото не одобрено,
  его видят только сам человек и команда; другие видят человека без фото.
  Ждать проверки не нужно: Rida работает сразу.
- Команда: очередь `GET /admin/faces`, фото, решение «Rasm mos» или
  «Mos emas» с причиной (3 причины, `120`); карточка с кнопками в админ-боте;
  журнал `face_log`. Отказ: бот попутчика пишет причину и кнопку
  «Rasmni almashtirish». Одобренная заявка водителя одобряет и фото.

## Съёмка только фронтальной камерой (решение владельца 28.09)

- Фото профиля: только селфи на фронтальную камеру, у водителя и у пассажира.
  Открывается наша камера внутри Mini App с овалом для лица (решение владельца 29.09.2026).
  Если её нельзя открыть, кнопка открывает камеру телефона (`capture="user"`), галереи нет.
- Telegram Desktop и Web: камеры нет, кнопки загрузки нет. Человек видит
  подсказку добавить фото с телефона.
- Ограничение: на части телефонов браузер всё равно может предложить галерею,
  и узнать это из WebView нельзя. Защита: модерация аватара водителя (G06)
  и жалобы `fake_profile` (`17`).

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/me` | Состояние: `unregistered`, `blocked`, `active` с профилем |
| POST | `/me/registration` | Согласие, имя, пол, подписанный контакт |
| PUT | `/me/avatar` | Новое фото (`image/jpeg`, `image/webp`) |
| POST | `/me/write-access` | Разрешил ли человек боту писать |
| GET | `/users/:id` | Публичный профиль (`:id` публичный; Telegram ID отвечает 404) |
| GET | `/users/:id/avatar` | Фото, если правила `05` разрешают |

Схемы: `packages/contracts/src/users.ts`. Код: `apps/backend/src/modules/users`,
экраны: `packages/ui/src/account`.
