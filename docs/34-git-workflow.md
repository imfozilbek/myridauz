# 34. Git: ветка на каждую цель

> **Кратко:** Каждая цель делается в своей ветке. Цель закрыта, только когда ветка слита в `main` без конфликтов и в `main` всё работает: CI зелёный, деплой прошёл.

## Правило (решение владельца)

- **Одна цель = одна ветка.** Имя: `goal/gNN-коротко`, например
  `goal/g01-monorepo`. Для OPS-целей ветка не нужна.
- Ветка создаётся от **свежего `main`**.
- **Закрытие цели** = ветка слита в `main` **без конфликтов**,
  и в `main` это **работает**.
- Владелец дал разрешение: Claude создаёт ветки целей и ветку `main`,
  открывает PR и сливает его после подтверждения владельца (`33`).

## Порядок работы по цели

1. `git fetch`, новая ветка `goal/gNN-...` от `origin/main`.
2. Работа маленькими понятными коммитами.
3. Перед PR: слить свежий `main` в ветку, решить конфликты,
   локально пройти все барьеры (`31`).
4. PR `goal/gNN-...` → `main`. Описание PR: что сделано, скриншоты
   (`33`), чек-лист Definition of Done.
5. CI на PR зелёный. Конфликтов нет.
6. Владелец подтверждает пункты «Проверка владельцем».
7. Слияние: **squash merge** (одна цель = один коммит в `main`).
8. После слияния: CI на `main` зелёный, деплой прошёл (с G03),
   быстрая проверка в проде.
9. Ветка цели удаляется. Статус цели в `goals/INDEX.md`: «Выполнена».

## Если в main сломалось

- Сразу исправление в новой ветке `fix/...` (тот же порядок) или
  откат слияния (`git revert`), если исправление долгое.
- Запись в журнал уроков (`26`).

## Первый запуск (G01)

- Сейчас в репозитории одна ветка с документами. В G01 Claude создаёт
  `main` от неё, и дальше все цели идут от `main`.
- Владелец делает `main` веткой по умолчанию и включает защиту `main`
  (шаги даёт Claude).
