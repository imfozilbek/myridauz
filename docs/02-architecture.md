# 02. Архитектура продукта

## Три роли и три пары «бот + Mini App»

| Роль | Бот и Mini App | Доступ |
|---|---|---|
| Пассажир | Бот пассажиров + Mini App пассажиров | Любой пользователь |
| Водитель | Бот водителей + Mini App водителей | Работа — только после модерации |
| Админ | Админ-бот + админ Mini App | Только команда Rida |

## Итого по продукту

- **3 бота + 3 Mini App** (пассажир, водитель, админ).
- **1 лендинг** (`myrida.uz`) — в конце.
- **Telegram-каналы** с поездками — `15-channels.md`.

## Почему два отдельных бота (пассажир и водитель)

- Бот водителя — отдельный кабинет водителя: его поездки, брони, кошелёк.
- Чистый интерфейс: у каждой роли — только свои функции.
- Если Telegram ограничит один бот, второй продолжит работать.
- Цена решения: путь «пассажир → водитель» длиннее. Решение — ниже.

## Правила

- **Один общий backend** на Cloudflare. Боты и Mini App — тонкий слой
  поверх общего backend.
- **Один пользователь = одна запись в базе** (по Telegram ID), даже если он
  пользуется несколькими ботами. Повторно вводить данные не нужно.
- В боте пассажиров есть кнопка «Haydovchi bo'lish» — deep link в бот водителей.
- Уведомления: пассажир получает их от бота пассажиров,
  водитель — от бота водителей.
- Админ: доступ по списку Telegram ID + роль в базе.
  Функции: модерация водителей, блокировки, таблица цен, статистика.
