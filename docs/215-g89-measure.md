# 215. G89: замер контроля логики «до» и «после»

> **Кратко:** как G89 мерил, насколько логика под контролем тестов: уровни тестов по цепочкам, покрытие веток и мутационный счёт Stryker для `domain` и `application` backend. «До»: ветка `main` 20.10.2026 утром; «после»: ветка G89. Цели DoD: ветки не ниже 90 %, мутационный счёт не ниже 80 %.

## Как мерили

- **Уровни тестов по цепочкам:** карта `206`, `207`, `208`. У каждой цепочки стоит тест и его уровень: `unit` (сценарий на памяти или тестовой D1), `api` (весь Worker на тестовой D1), `stand` (Playwright, `75`), `e2e`. Цепочки с одним уровнем или одним случаем: разделы «Где тестов мало» в тех же файлах.
- **Ветки:** `vitest --coverage` (v8) только по `apps/backend/src/modules/*/{domain,application}`, все тесты backend.
- **Мутации:** Stryker 10 меняет код по мелочи (знак, условие, число) и запускает тесты. Мутация, которую ни один тест не заметил, «выжила»: тест проходит это место, но ничего не проверяет. Счёт: доля замеченных среди всех с покрытием и без.
  - Запуск: `pnpm mutation` (около 1,5 часа на 3 потоках). Повтор с `--incremental` берёт прошлые итоги для неизменного кода.
  - Прогон идёт на месте (`inPlace`), все тесты backend, без «related» (урок №359); перед прогоном сверить число тестов с `vitest run` того же пакета.
  - Без тестов сетки карты (`*-grid.test.ts`, 58 000 точек): их гоняет CI.

## Где контроль слабее

- Выжившие мутации остаются в формулах текста и порядке списков: тесты проверяют смысл, а не каждую строку. Список по файлам: артефакт `mutation-report` еженедельного прогона.
- Экраны (`packages/ui`) мерятся покрытием строк 70 % и стендом, мутаций для них нет: прогон шёл бы много часов.
