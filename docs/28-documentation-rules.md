# 28. Правила документации

> **Кратко:** Как пишем документы: cognitive ease, Clean Docs, нумерация, лимит 150 строк, индекс.


## Cognitive ease в документах

- Документы пишутся по тем же правилам, что и ответы: коротко, просто,
  главное сверху, списки и таблицы вместо длинных абзацев.
- **Каждый документ начинается с блока `> **Кратко:**`** (1 или 2 предложения,
  суть документа).
- Решённое помечается «решено», предложения Claude помечаются «предложено».

## Clean Docs (чистая документация)

- **Одна тема = один документ.** Не смешивать темы.
- **Один источник правды:** факт записан в одном месте, остальные
  документы ссылаются на него (`NN-файл.md`), а не копируют.
- **Без устаревшего:** при каждом решении обновить все документы,
  где эта тема упоминается. Старое удалить, не оставлять рядом.
- Единые термины (глоссарий в `01` и `25`).
- Без тире (правило выше).

## Структура

- **Любая тема обсуждения с владельцем** фиксируется в документе в `docs/`.
- Имя файла: `NN-тема-на-английском.md`: номер по порядку (01, 02, …)
  и понятное название в kebab-case. Заголовок файла: `# NN. Тема`.
- **Лимит: 150 строк на файл.** Если файл больше: разбить тему на две
  отдельные подтемы (два файла со своими номерами).
- Новая тема: новый файл со следующим свободным номером.
  Уточнение старой темы: правка существующего файла.
- **`docs/INDEX.md`**: индекс всех документов. Обновлять при каждом
  добавлении, переименовании или разбиении файла.
- Нерешённые вопросы: в `docs/10-open-questions.md`. Когда вопрос решён,
  решение переносится в профильный документ.
- Этот файл (`CLAUDE.md`) тоже должен знать, где что лежит: карта ниже.
