# 64. Живое обновление экранов (realtime, G19)

> **Кратко:** Экраны 3 Mini App обновляются сами, когда действует другой человек: водитель подтвердил бронь, пассажир отменил, пришла заявка водителя или жалоба. Сервер шлёт в личный канал человека сигнал «изменилось», открытый экран тихо берёт свежие данные из API. Запасной путь: обновление при возврате в Mini App. Сделано 30.09.2026 (проблема владельца).

## Как работает

1. Действие человека A меняет данные и ставит уведомление бота человеку B (`notify`, `docs/53`).
2. В тот же момент backend шлёт сигнал в личный канал B: Durable Object `UserFeed`, один на человека.
3. Канал отправляет `{"type":"changed"}` только в ту Mini App B, чей бот говорит (пассажир, водитель или админ).
4. Открытый экран B тихо загружает свежие данные: старые остаются на экране, без скелетона и мигания.

| Часть | Где |
|---|---|
| Кому сигнал: правило | `apps/backend/src/modules/feed/domain/feed-signals.ts` |
| Личный канал | `modules/feed/infrastructure/user-feed.ts` (WebSocket Hibernation) |
| Билет и сокет | `POST /feed/ticket`, `GET /feed/socket` (`modules/feed/http/feed-routes.ts`) |
| Общий подписанный билет | `shared/auth/signed-ticket.ts` (чат и канал, у каждого свой ключ) |
| Сигнал из уведомлений | `modules/notifications/index.ts` (`notify`) |
| Сигнал модерации водителей | `modules/drivers/infrastructure/signalled-notifier.ts`: карточка идёт в Telegram напрямую, сигнал команде и водителю |
| Сигнал правки кошелька | `modules/wallet/http/wallet-routes.ts`: владелец поправил, у водителя обновился Hamyon |
| Клиент | `packages/ui/src/feed/` (`FeedProvider`, `useFeedChange`) |
| Тихое обновление | `useLoad` (`market/use-list.ts`) и 3 экрана со своей загрузкой |
| Возврат в приложение | `telegram/app-visible.ts` (`visibilitychange`, Telegram `visibility_changed`) |

## Безопасность (`32`)

- В сигнале нет личных данных: только «изменилось». Данные экран берёт из API с подписью Telegram.
- Второй вид сигнала (G54, `115`): `{"type":"call","chat":"<ключ чата>"}`. Mini App открывает чат звонка сама. Сигнал «изменилось» ещё и играет уведомление Rida.
- Сокет открывается только по билету: подпись HMAC, срок 60 секунд, свой ключ `feed-ticket`. Билет чата канал не открывает (тест).
- Человек слышит только свой канал: имя канала берётся из подписанного билета, не из адреса.
- Ошибка канала не ломает действие: сигнал уходит через `allSettled`, ошибки канала не попадают в аналитику ошибок.

## Какие экраны обновляются

Все экраны с загрузкой через `useLoad` (16) и 3 экрана со своей загрузкой.

| Mini App | Экраны |
|---|---|
| Пассажир | Главный экран: «Yaqin safarlar» (G25), Mening safarlarim (брони, заявки, предложения), история, любимые водители, подписки, поездка по ссылке, результаты поиска, отзыв |
| Водитель | Главный экран: поездки и «N ta yangi soʻrov» (G25), Mening safarlarim (поездки, брони, предложения), брони поездки, поиск заявок, Hamyon |
| Админ | заявки водителей, жалобы и жалоба, кошельки, поездки команды, Statistika, каналы |

- Результаты поиска и поездка по ссылке: чужие брони не шлют сигнал ищущему, они обновляются при возврате в приложение.
- Новые экраны с `useLoad` получают обновление сами.
- Пока не обновляются сами (аудит `65`, B2): экран статуса заявки водителя (сигнал приходит, экран его не слушает), открытые бронь, поездка и предложение (копия на момент открытия), профиль.

## Соединение

- Одно соединение на Mini App, открывается при запуске.
- Пропал сокет: новая попытка через 1, 2, 4 … 30 секунд. Возврат в приложение открывает сразу.
- Нет билета (нет сети): те же паузы, без ошибок на экране.

## Нагрузка (`61`)

| Что | В день на 2 000 активных |
|---|---|
| Сигналы (запросы к Durable Object) | ~5 400 (600 броней × ~9 сообщений) |
| Подключения (билет + сокет) | ~4 000 сессий, ~8 000 запросов Workers |
| Спящие сокеты | не стоят ничего (Hibernation) |

Помещается в Workers Paid $5 с большим запасом (`61`).
