# 31. Тесты и барьеры качества

> **Кратко:** Любая логика закрыта тестами. Автоматические барьеры в CI не пропускают неправильный код в прод: без зелёного CI нет слияния и нет деплоя.

## Принцип (решение владельца)

- Всё закрывается тестами.
- Барьеры (quality gates) **не пропускают неправильную логику до прода**.
- Код без тестов не принимается.

## Пирамида тестов

| Уровень | Что проверяем | Инструмент | Сколько |
|---|---|---|---|
| Unit | `domain`: правила (цена, комиссия, бонус, отметка «ayol bor», маскировка контактов) | Vitest | Больше всего |
| Use case | `application`: сценарии (создать поездку, подтвердить бронь, отменить) с фейковыми репозиториями | Vitest | Много |
| Интеграция | Worker + D1 + Durable Objects локально | Vitest + `@cloudflare/vitest-pool-workers` | Главные пути |
| Контракт | Схемы API (`packages/contracts`) совпадают у backend и Mini App | Vitest + zod | Все эндпоинты |
| UI | Компоненты и экраны Mini App | Vitest + Testing Library | Главные экраны |
| E2E | Главные сценарии целиком в браузере | Playwright | 5 … 10 сценариев |

## Обязательные тесты (критичная логика)

- Деньги: комиссия 10%, минимум 3 000, бонус, сгорание, возвраты (`12`).
- Цена: формула, округление, пределы 30 000 … 600 000 (`16`, `23`).
- Приватность: контакты не утекают ни в одном ответе API (`07`),
  маскировка в чате, фото попутчика не видно водителю (`05`).
- Отметка «Mashinada ayol bor»: ставится и снимается правильно (`06`).
- Запрет поездок внутри города (`14`).
- Права доступа: попутчик, водитель, админ; проверка подписи initData.

## Правило покрытия

- `domain` и `application`: покрытие строк не ниже 90%.
- Остальное: не ниже 70%.
- Покрытие не может падать: CI сравнивает с основной веткой.

## Барьеры в CI (все обязательны)

1. Формат (Prettier).
2. Линтер (ESLint): 150 строк, границы модулей, без `any`, без HEX, без «Rida» в коде.
3. Типы (`tsc --noEmit`, `noUnused*`).
4. Неиспользуемый код (`knip`).
5. Тесты unit, use case, интеграция, контракт, UI.
6. Покрытие не ниже порога.
7. E2E главных сценариев.
8. Проверка секретов (`32-ci-security.md`).
9. Длинные тире и имя бренда в текстах (`scripts/check-text.mjs`).

Команды и где настроен каждый барьер: `45`.

- Любой барьер красный: слияние запрещено (branch protection).
- Деплой в прод только после зелёного CI на основной ветке.

## Правила написания тестов

- Тест рядом с кодом: `create-trip.ts` → `create-trip.test.ts`.
- Баг найден: сначала тест, который его ловит, потом исправление.
  Запись в журнал уроков (`26`).
- Тесты быстрые и без сети: внешние API (Telegram) подменяются.
