# 213. G89: находки P0, P1, P2

> **Кратко:** аудит G89 нашёл 93 ошибки логики (84 без дублей); две независимые проверки подтвердили все 14 находок P0 и P1. Исправлено 92 из 93 (99%), 1 отклонена. 9 находок сделаны по советам владельцу от 20.10.2026 и ждут его подтверждения вместе с новыми текстами; P3 и решения: `214`.

## Как искали

- Шесть областей, у каждой свой аудитор: поездка водителя (T), бронь и встреча (B), деньги и аккаунты (M), связь и доставка (C), команда и доверие (A), экраны Mini App (U).
- Карта цепочек: каждый вход (маршрут API, кнопка бота, Cron, очередь, Durable Object, действие экрана) прослежен до SQL в D1 и до побочных действий (сообщения, посты, сигналы).
- Таблицы состояний: у каждого перехода пять вопросов: кто, когда, дважды, в одну секунду, где застревает.
- Пары: роль, состояние человека, статус, время, деньги, платформа, сеть. Искали сочетания, которых код не ждёт, и споры кода с решениями владельца в docs.
- Правило «сначала падает»: исправление входит вместе с тестом, который до него падал. Исключение: только docs (M17, U16). Тесты C1, C2 и M14 дописаны отдельным коммитом `5870664`.

## Где проверки разошлись

- Обе проверки признали все 14 находок настоящими ошибками. Спорили только о важности и деталях.
- T3, C1, M2: проверка 1 ставит P2 (узкое окно гонки, сокет живёт недолго), проверка 2 оставляет P1.
- B1, C4: обе ставят P2. Ранний «Yetib keldim» возможен только ручным запросом; сообщение чата не теряется, не приходит только звонок бота.
- C7: проверка 1 «частично»: неверного сообщения близким нет, неверен только экран слежения.
- B3: проверка 2 «частично»: на экране заявки есть «Bekor qilish», человек не заперт, но никто не говорит ему, что мест нет.
- T2: проверка 1: «починить нельзя» сказано слишком сильно, место можно отменить по одному, но об этом никто не знает.
