# 32. Безопасный CI в открытом репозитории

> **Кратко:** Репозиторий публичный, CI на бесплатном GitHub Actions. Секреты никогда не попадают в код и в чужие pull request. Секреты бота живут только в Cloudflare, в GitHub только один узкий токен деплоя под защитой.

## Условия (решение владельца)

- Репозиторий **открытый** (public).
- CI на **GitHub Actions**. Для публичных репозиториев стандартные
  раннеры бесплатны, платные минуты другого проекта не тратятся.
- CI должен быть **полностью безопасным**.
- Документы `docs/` остаются в публичном репозитории (решение владельца).
  Секретов в них нет и быть не должно.

## Где живут секреты

| Секрет | Где хранится | В GitHub? |
|---|---|---|
| Токены 3 ботов, секрет вебхука | Cloudflare (`wrangler secret`) | **Нет** |
| Ключи Realtime, прочие ключи сервисов | Cloudflare (`wrangler secret`) | **Нет** |
| Токен деплоя Cloudflare (узкие права) | GitHub Environment `production` | Да, под защитой |
| ID аккаунта Cloudflare | GitHub Environment `production` | Да |

- Локально: `.dev.vars` в `.gitignore`. В репозитории только
  `.dev.vars.example` без значений.
- Токен деплоя: только нужные права (Workers, D1, R2, Pages) и только
  один аккаунт. Меняется раз в 90 дней.

## Правила workflow

1. **CI для pull request** (`pull_request`): без секретов вообще.
   Код из чужих форков не видит ни одного секрета.
2. **Запрещено** `pull_request_target` и запуск кода из PR с секретами.
3. **Деплой** только из основной ветки (`push` в `main`) и только
   через Environment `production`:
   - правило: деплой только из `main`;
   - обязательное подтверждение владельцем (required reviewer).
4. `permissions:` минимальные: по умолчанию `contents: read`.
5. Сторонние actions закреплены по полному SHA коммита, не по тегу.
6. Первые запуски CI от новых внешних участников требуют одобрения
   (настройка репозитория).
7. Логи CI не печатают секреты и переменные окружения.

## Защита в репозитории (бесплатно для public)

- Secret scanning и **push protection**: GitHub блокирует push с ключом.
- `gitleaks` в CI: второй барьер от утечки ключей.
- Dependabot: обновления и уязвимости зависимостей.
- CodeQL: анализ безопасности кода.
- Branch protection на `main`: только через PR, CI зелёный,
  без force push.

## Защита приложения (ключи в открытом коде не нужны)

- Вебхуки ботов проверяют `secret_token` Telegram.
- API проверяет подпись initData каждого бота.
- Бизнес-правила (цены, комиссия) в открытом коде: это нормально,
  значения живут в настройках (`23`), доступ к настройкам только админам.

## Доступ Claude к Cloudflare (решение владельца)

Цель: Claude сам автоматизирует инфраструктуру, участие владельца минимально.

- Ключи **никогда не присылаются в чат** и не попадают в репозиторий.
- Владелец добавляет их в настройки облачного окружения Claude
  (меню окружения в заголовке сессии → Edit → переменные окружения).
  Новая сессия их видит.

| Переменная | Что это |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Токен API с правами на аккаунт и зону `myrida.uz` |
| `CLOUDFLARE_ACCOUNT_ID` | ID аккаунта |
| `PASSENGER_BOT_TOKEN` | Токен бота пассажиров |
| `DRIVER_BOT_TOKEN` | Токен бота водителей |
| `ADMIN_BOT_TOKEN` | Токен админ-бота |

- Права токена Cloudflare (Custom token): на аккаунт: Workers Scripts,
  Workers KV, Workers R2, D1, Pages, Queues, Realtime, чтение аналитики
  и настроек; на зону `myrida.uz`: DNS, Workers Routes, чтение зоны.
- Токены ботов Claude сам кладёт в Cloudflare (`wrangler secret`).
- **Решение владельца на время разработки:** ключи можно передать в чате.
  Claude хранит их в локальном файле `.env` (в `.gitignore`, в репозиторий
  не попадает). Риск принят: на время разработки ценного нет,
  карта к Cloudflare не привязана (бесплатный тариф).
- Файл `.env` живёт только в текущем контейнере и пропадает вместе с ним.
- **Перед запуском все ключи обязательно ротируются** (неделя 13).

## Если ключ всё же утёк

1. Сразу отозвать ключ (BotFather `/revoke`, Cloudflare).
2. Выпустить новый, положить в Cloudflare / Environment.
3. Запись в журнал уроков (`26`).
