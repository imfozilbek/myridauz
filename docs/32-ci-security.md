# 32. Безопасный CI в открытом репозитории

> **Кратко:** Репозиторий публичный, CI на бесплатном GitHub Actions. Секреты никогда не попадают в код и в чужие pull request. Секреты бота живут только в Cloudflare, в GitHub только один узкий токен деплоя под защитой.

## Условия (решение владельца)

- Репозиторий **открытый** (public).
- CI на **GitHub Actions**. Для публичных репозиториев стандартные
  раннеры бесплатны, платные минуты другого проекта не тратятся.
- CI должен быть **полностью безопасным**.
- Документы `docs/` остаются в публичном репозитории (решение владельца).
  Секретов в них нет и быть не должно.

## Где живут секреты

| Секрет | Где хранится | В GitHub? |
|---|---|---|
| Токены 6 ботов, секрет вебхука (свои в каждой среде, `179`) | Секреты Worker своей среды | **Нет** |
| Ключи аналитики, Realtime, прочие ключи сервисов | Секреты Worker своей среды | **Нет** |
| Токен деплоя `rida-<среда>-deploy` (узкие права) | GitHub Environment `internal` (первый аккаунт) и `production` (новый), `179` | Да, под защитой |
| ID аккаунта Cloudflare | GitHub Environment `internal` и `production` | Да |

- Карта всех ключей обеих сред: `179` («Ключи обеих сред»). Один ключ: одно место и одно дело.
- Локально: `.dev.vars` в `.gitignore`. В репозитории только
  `.dev.vars.example` без значений.
- Токен деплоя (для CI): права из `179` и только один аккаунт.
- Это **другой** токен, не тот, что у Claude для настройки (ниже).
- `.dev.vars`: локальные значения для запуска Worker (wrangler), в `.gitignore`.

## Правила workflow

1. **CI для pull request** (`pull_request`): без секретов вообще.
   Код из чужих форков не видит ни одного секрета.
2. **Запрещено** `pull_request_target` и запуск кода из PR с секретами.
3. **Деплой** только из основной ветки (`push` в `main`) и только
   через Environment (`179`):
   - правило обоих: деплой только из `main`;
   - `internal` (среда команды): без подтверждения;
   - `production`: вернётся с новым аккаунтом (`179`), после `internal`, обязательное подтверждение владельцем (required reviewer).
4. `permissions:` минимальные: по умолчанию `contents: read`; job `changes` ещё читает `deployments` (только чтение, только на `main`).
5. Сторонние actions закреплены по полному SHA коммита, не по тегу.
6. Первые запуски CI от новых внешних участников требуют одобрения
   (настройка репозитория).
7. Логи CI не печатают секреты и переменные окружения.

## Защита в репозитории (бесплатно для public)

- Secret scanning и **push protection**: GitHub блокирует push с ключом.
- `gitleaks` в CI: второй барьер от утечки ключей. Файл gitleaks
  проверяется по SHA-256, checkout без сохранения токена (`45`).
  Правила по умолчанию и одно исключение в `.gitleaks.toml`: узбекское «keyin» (урок №297).
  Проверка видит все ветки: ложная тревога в чужой ветке краснит все PR.
- Dependabot: обновления и уязвимости зависимостей.
- `pnpm audit` в CI: PR с уязвимой зависимостью не сливается. Если уязвимость
  в зависимости чужого пакета: `pnpm.overrides` в корневом `package.json`.
- CodeQL: анализ безопасности кода.
- Branch protection на `main`: только через PR, CI зелёный,
  без force push.

## Защита приложения (ключи в открытом коде не нужны)

- Вебхуки ботов проверяют `secret_token` Telegram.
- API проверяет подпись initData каждого бота.
- Бизнес-правила (цены, комиссия) в открытом коде: это нормально,
  значения живут в настройках (`23`), доступ к настройкам только админам.

## Доступ Claude к Cloudflare (решение владельца)

Цель: Claude сам автоматизирует инфраструктуру, участие владельца минимально.

- Ключи **никогда не попадают в репозиторий**.
- Основной способ: владелец добавляет их в настройки облачного окружения Claude
  (меню окружения в заголовке сессии → Edit → переменные окружения).
  Новая сессия их видит.

| Переменная | Что это |
|---|---|
| `CLOUDFLARE_API_TOKEN` | `rida-internal-claude`: права деплоя (`179`) и Workers Tail: Read, первый аккаунт |
| `CLOUDFLARE_ACCOUNT_ID` | ID первого аккаунта |
| `PROD_CLOUDFLARE_API_TOKEN` | `rida-prod-claude`: то же на новом аккаунте |
| `PROD_CLOUDFLARE_ACCOUNT_ID` | ID нового аккаунта |

- Для Rida в окружении Claude только эти 4 переменные (карта владельца 15.10.2026, `179`).
- Токенов ботов в окружении Claude нет: окружение одно на все проекты, его видят все сессии.
  Токены ботов кладёт владелец в секреты Worker своей среды.
- Ключи в чат не передаются никогда: владелец пишет только «готово».
- Перед запуском все ключи заменены по карте; старые токены удалены (`179`).

## Если ключ всё же утёк

1. Сразу отозвать ключ (BotFather `/revoke`, Cloudflare).
2. Выпустить новый, положить в Cloudflare / Environment.
3. Запись в журнал уроков (`26`).
