# 67. Карта в Mini App: точка посадки попутчика

> **Кратко:** Попутчик выбирает точку посадки на карте внутри Mini App (G22, решение владельца 30.09.2026) и может найти место по названию (G23). Карта Узбекистана из OpenStreetMap лежит в нашем R2 и отдаётся через API. Внешних сервисов нет. Библиотека MapLibre: исключение из `19`, только на экране карты.

## Как это видит человек

- G24: точку выбирают на экране «Qayerdan / Qayerga» до поиска и при брони (`71`), а не после подтверждения. Карта точки обрезана по району под булавкой; поиск в другом районе снимает обрезку.
- Карта открывается у места человека, у другой точки маршрута или в центре Ташкента.
- **Граница страны (решение владельца 30.09.2026):** любая карта Mini App показывает только Узбекистан: снаружи затемнено, дальше границы карту не сдвинуть (`contracts/uzbekistan.ts`). Карта точки обрезана ещё уже, по своему району (`48`).
- Булавка стоит в центре карты, название места под ней. Человек двигает карту, потом «Shu yerda».
- **Экран точки (G36, `100`):** карта занимает место над шторкой снизу; в шторке заголовок, подсказка, поиск и 2 последних места. Шторка ничего не закрывает на карте. При поиске шторка раскрывается на весь экран; выбор места опускает её.
- «Mening joylashuvim» (справа сверху на карте) ведёт карту к месту, где человек стоит. Нужно разрешение в Telegram (Bot API 8.0); в старом клиенте спрашивает браузер.
- Поиск (G23): поле «Mahalla, koʻcha yoki moʻljal». Список: иконка вида, название, вид и район. Нажатие ведёт карту к месту, дальше «Shu yerda». Карта меняет размер вместе со шторкой и держит место под булавкой (`maplibre-engine.ts`). Ничего не нашлось: совет написать иначе или подвинуть карту.
- Водитель видит точки подтверждённых попутчиков на «Safar xaritasi» (G24).
- Карта не загрузилась: «Xarita yuklanmadi», «Qayta urinish» и подсказка выбрать место из списка районов (`14`).
- Внизу подпись «© OpenStreetMap»: её требует лицензия ODbL.

## Первая загрузка

- Карта попадает в R2 только после запуска workflow «Map data» владельцем (GitHub → Actions → «Map data» → Run workflow, ветка `main`). До этого экран карты показывает «Xarita yuklanmadi» и путь через список районов.
- G24: миграция 0023 меняет схему индекса поиска и очищает его. После деплоя владелец запускает «Map data», иначе поиск пуст.
- Ключу `CLOUDFLARE_API_TOKEN` в GitHub нужно право «Workers R2 Storage: Edit» (`32`), иначе запись в R2 ответит 403.

## Как обновить карту

1. В `packages/contracts/src/map.ts` поменять `MAP_ARCHIVE` на дату данных новой сборки в копии. Если дата не совпала, скрипт падает и пишет нужное имя.
2. PR, слияние, деплой из main.
3. В GitHub запустить workflow «Map data» (только с main, через Environment `production`, `32`).
4. Скрипт `pnpm map-data --brand=rida`: сверяет дату, вырезает Узбекистан, заново строит индекс поиска в D1 (около 65 тыс. строк: на бесплатном тарифе не больше одного раза в день), проверяет размер (не больше 300 МБ на один put), кладёт файл и шрифты в R2.

Новое имя файла: старые части в кэше никогда не смешиваются с новыми.

**Решение владельца 30.09.2026:** перед запуском карту обновить на свежую сборку (неделя 18, `62`).

## Как устроено

- **API:** `GET /map/<файл>.pmtiles` отдаёт только часть файла (заголовок `Range`, не больше 2 МБ), `GET /map/fonts/<шрифт>/<диапазон>.pbf` отдаёт шрифт. Публично: данные OSM, о людях ничего. CORS только для Mini App.
- **Кэш:** часть, прочитанная из R2 один раз, лежит в кэше Cloudflare; телефону `Cache-Control: immutable` на неделю.
- **Точки (G24):** приходят вместе с бронью `POST /trips/<id>/bookings` (`35`). Название под булавкой: `GET /passenger/map/where`, граница района: `GET /passenger/map/borders/<id>`.
- **Mini App:** MapLibre и PMTiles грузятся отдельным куском (289 КБ в сжатом виде) только при открытии карты. Обёртка в `packages/ui/src/map`, стиль светлый (`20`), булавка цвета бренда.
- **Тесты:** unit на подделке карты (jsdom не рисует WebGL); e2e в настоящем браузере на куске карты Ташкента (`e2e/fixtures/map`, 2 МБ).

## Нагрузка (подробно `61`)

- Одно открытие карты: около 30 запросов к Worker (заголовок, каталоги, плитки, шрифты, движение карты).
- 600 броней в день: около 20 000 запросов Worker в день. R2: не больше 0,6 млн чтений в месяц при лимите 10 млн, хранение 0,25 ГБ из 10 ГБ.
