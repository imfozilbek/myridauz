# 224. Команда исправляет свои решения по заявкам водителей

> **Кратко:** просьба владельца 06.11.2026: модератор одобрил заявку водителя, хотя номер машины на фото не совпал с номером в тексте. Сейчас после одобрения команда ничего исправить не может. План: модератор видит свои решения («Mening qarorlarim»), у одобренного водителя есть «Mashinani tuzatish» (номер, модель и цвет по фото), «Tuzatishga qaytarish» (плохое фото) и у владельца «Rad etishni bekor qilish». Исправление доходит до живых поездок, постов, броней и бота. Все слова и вид: черновик, на согласие владельца. Цель: G95.

## Случай владельца

- Водитель написал один номер, на фото спереди другой.
- Модератор нажал «Tasdiqlash» и не заметил разницы.
- Попутчики ищут машину по номеру: неверный номер мешает встрече и доверию.

## Что сейчас (код 06.11.2026)

| Что | Как сейчас |
|---|---|
| Решение по заявке | только по заявке, которая ждёт проверки (`decide` в `drivers/domain/application.ts`) |
| «Raqamni tuzatish» | есть, но только до одобрения (`50`, решение владельца 29.09.2026) |
| После одобрения | у команды нет ни одной кнопки про машину; водитель меняет машину сам и снова идёт на проверку |
| «Rad etish» | последнее слово (G75, `120`): ошибочный отказ не исправить |
| Свои решения модератора | не видны: плитка «bugun qildingiz» только число |
| Машина в поездке | копия в каждой поездке и предложении (`car_plate`, миграция `0017`): неверный номер уже в живых поездках |
| Посты каналов и группы | номера нет, модель и цвет есть (`15`); правка постов уже есть (`refreshPosts`) |

## План (совет)

### 1. Где команда находит своё решение

- Модератор: плитка «bugun qildingiz» открывает «Mening qarorlarim»: свои решения по заявкам за 7 дней, новые сверху.
- Владелец: то же через «Jurnal» (запись о заявке открывает дело) и через «Odam» (строка машины).
- Дело открывается как в «Navbat»: фото спереди, номер, модель, цвет, «Oldingi qarorlar». Внизу действия по статусу.

### 2. «Mashinani tuzatish»: данные не совпали с фото

- Для одобренного водителя. Шторка как «Raqamni tuzatish»: номер по той же маске, модель и цвет кнопками.
- Сервер: только `approved`; номер по маске; предупреждение, если номер есть в другой заявке.
- Водитель остаётся водителем, новой проверки нет: фото уже проверено, неверны только слова.
- Новая машина сразу везде:
  - в живых поездках и предложениях водителя (не в прошлых);
  - посты в каналах и группе правятся (`refreshPosts`), если сменились модель или цвет;
  - карточка для близких показывает новый номер.
- Сообщения бота:
  - водителю: «Davlat raqami rasm boʻyicha tuzatildi: …» (текст уже есть) и новые строки для модели и цвета;
  - попутчикам с живой бронью: новый номер машины (новый текст).
- Запись в `application_log` и «Jurnal»: кто, когда, «было → стало».

### 3. «Tuzatishga qaytarish»: плохое фото одобрили по ошибке

- Для одобренного водителя: на фото нет номера, другая машина, фото не читается.
- Причины галочками, как у «Tuzatish» сейчас. Статус `changes_requested`.
- Правило `50` без изменений: живые поездки, брони и посты живут дальше; новые поездки ждут нового «Tasdiqlash».
- Водитель получает то же сообщение бота, что при «Tuzatish».

### 4. «Rad etishni bekor qilish»: отказ по ошибке

- Только владелец. Заявка снова в «Navbat» (`pending`), решает любой из команды.
- Водителю сообщение бота: заявку проверят ещё раз (новый текст).
- Запись в «Jurnal».

## Что не входит

- Решения по жалобам и фото лица: блок уже снимается («Blokdan chiqarish»), фото лица человек меняет сам.
- Прошлые поездки: в них машина остаётся как была.

## Оценка

Около 7 часов: сервер 2, экраны 3, бот и тексты 1, тесты и стенд 1 (`CLAUDE.md`: 1 день оценки ≈ 1 час).
