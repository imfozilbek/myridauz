# 75. Стенд: вся Rida на одном компьютере

> **Кратко:** `pnpm stand` поднимает всю систему локально: тот же backend, база со всеми миграциями, настоящая карта Узбекистана и её индекс поиска, три Mini App. Вход через Telegram подписывается тестовыми токенами ботов. Они создаются на этом компьютере, поэтому ничего не уходит в Cloudflare или Telegram. `pnpm stand:check` проходит сценарии целей на стенде, как человек на телефоне, и снимает скриншоты. Просьба владельца 01.10.2026: Claude должен сам проверять цели на полной системе.

## Чем стенд отличается от e2e

| | e2e (`pnpm e2e`) | Стенд (`pnpm stand:check`) |
|---|---|---|
| Backend | Заглушки ответов | Настоящий Worker (`wrangler dev`) |
| База | Нет | D1 со всеми миграциями, справочник, пятаки |
| Карта и поиск мест | Заглушки | Карта OSM и индекс 64 000+ мест |
| Вход через Telegram | Подпись `test` | Настоящая подпись тестовым токеном бота |
| Люди и поездки | Выдуманные в тесте | Создаются через API, как в приложении |
| Где идёт | CI на каждый PR | У Claude перед PR цели |

## Команды

| Команда | Что делает |
|---|---|
| `pnpm stand` | Поднимает стенд и держит его; данные прошлых запусков остаются |
| `pnpm stand --fresh` | То же, но с чистой основы: людей, поездок и броней нет |
| `pnpm stand:check` | Поднимает стенд с `--fresh`, заполняет его и проходит все сценарии (G21, G24, G26, G27): около 3 минут |
| `STAND_REUSE=1 pnpm stand:check <файл>` | Проходит сценарии на стенде, поднятом вручную: виден весь журнал Worker. Данные не чистые, лимиты людей могут быть заняты |

Первый запуск скачивает карту (около 250 МБ) и строит индекс поиска: около 5 минут. Дальше стенд поднимается примерно за минуту.

## Адреса

| Что | Адрес |
|---|---|
| Backend | `http://localhost:8787` |
| Mini App попутчика | `http://localhost:4201` |
| Mini App водителя | `http://localhost:4202` |
| Админка | `http://localhost:4203` |

Каждая Mini App обращается к своему же адресу. Сервер стенда (`scripts/stand/serve-app.mjs`) отдаёт её файлы, а остальные запросы передаёт backend, вместе с WebSocket чата и живых экранов.

## Как устроен

| Часть | Где |
|---|---|
| Пути, порты, Telegram id владельца | `scripts/stand/paths.ts` |
| Запуск: токены, миграции, карта, сборка, серверы | `scripts/stand/stand.mjs` |
| Карта и индекс в локальный стенд | `pnpm map-data --brand=<brand> --local` |
| Подпись входа и телефона, открыть Mini App как человек | `e2e/stand/stand-kit.ts` |
| Люди стенда: у каждой цели свой водитель и маршрут | `e2e/stand/people.ts` |
| Регистрация людей, заявки водителей, одобрение владельцем | `e2e/stand/seed.ts` |
| Поездки, брони, ответы водителя через API | `e2e/stand/market-kit.ts` |
| Что прислали боты, Cron сразу, сдвиг времени в базе | `e2e/stand/stand-tools.ts` |
| Сценарии G27: ошибки API, ожидание сообщения бота, кошелёк, заявки | `e2e/stand/g27-kit.ts` |
| Обход экранов: снимок после данных и карты, проверка «шире экрана» | `e2e/stand/screen-tour.ts` |
| Сценарии целей | `e2e/stand/gNN.spec.ts` |
| Сценарии G27 по ролям | `e2e/stand/{passenger,driver,system,team,family,edges,screens}-*.spec.ts` |
| Настройки Playwright стенда | `playwright.stand.config.ts` |

Данные лежат в `.stand/` (в `.gitignore`):
- `state`: база, файлы, Durable Objects текущего стенда;
- `base`: чистая основа после миграций и карты;
- `dev.vars`: тестовые токены ботов.

## Безопасность

- Токены стенда случайные и создаются при первом запуске. С Telegram они не работают.
- Настоящие ключи стенду не нужны. Стенд их не читает и в Cloudflare ничего не пишет.
- Боты на стенде говорят с заглушкой Telegram (`scripts/stand/telegram-stub.mjs`, `TELEGRAM_API_URL`). Она запоминает каждое сообщение, кнопку и пост в канале; в настоящий Telegram ничего не уходит. Поэтому посты в каналы на стенде включены (`CHANNEL_POSTS:on`).
- `wrangler dev` запускается с `--local-upstream localhost:8787`. Без этого Worker считает своим адресом домен бренда и строит адреса сокетов на прод (урок №56).
- Каждый сценарий падает, если Mini App обратилась к внешнему адресу: такой запрос или сокет блокируется и попадает в отчёт (`outsideCalls`).

## Сценарии G26

`e2e/stand/g26.spec.ts`: 4 проверки владельца и проверка сервера. Скриншоты лежат в `screenshots/stand/g26/`, сначала Android 360 px.

1. Водитель Ташкент → Ургут видит пятак направления и публикует «Ikkalasi ham».
2. Попутчица «из дома»: точка посадки в Ташкенте, дом в Ургуте, проверка, отправка.
3. Попутчица с пятака: точку посадки не спрашивают, пятак виден в проверке.
4. Поиск места находит только внутри зоны поездки: в Ташкенте «Registon» находит кафе и улицы Ташкента, но не площадь в Самарканде; в Ургуте «bozor» находит только рынки Ургута.
5. Сервер сам отклоняет бронь с точкой вне зоны поездки (`bookings.outside_area`).

## Сценарии G21 и G24

`e2e/stand/g21.spec.ts`: 3 проверки владельца G21 (`docs/65`), скриншоты в `screenshots/stand/g21/`.

1. Плохая сеть: экран ошибки, «Назад» ведёт на главный экран, после сети экран грузится. Чат после обрыва соединения сам переподключается, сообщение уходит.
2. Водитель отменяет бронь: открытый экран попутчицы сам меняется на «Haydovchi bekor qildi».
3. Кнопка бота открывает свою бронь: Mini App открыта с `?booking=<id>`, как её открывает кнопка «Ochish». Как бот строит саму кнопку, проверяет unit-тест.

`e2e/stand/g24.spec.ts`: проверки владельца G24 №3 и №4, скриншоты в `screenshots/stand/g24/`. Проверки №1 и №2 после G26 стали бронью G26.

1. Запросы мест рядом с маршрутом идут первыми: «Bu safarga mos» (до 10 км лишнего пути), ниже «Boshqa soʻrovlar».
2. «Safar xaritasi»: точки подтверждённой брони, «Yoʻl koʻrsatish» открывает Yandex с маршрутом; у отменённой брони точек нет.

## Сценарии G33

`e2e/stand/g33.spec.ts`: «Назад», прокрутка и закрытие (`94`) на Android и iOS, скриншоты в `screenshots/stand/g33/before/` и `after/` (`G33_SHOTS=before` для «до»).

1. Длинный список поездок → поездка открыта сверху → «Назад»: тот же список на том же месте, без скелетона.
2. Новая поездка до комментария → приложение закрыто → черновик вернулся.
3. Камера фото машины: «Назад» закрывает камеру, шаг остаётся.
4. Чат не прыгает вниз, пока человек читает; «Назад» во время звонка выключает микрофон.

## Чего стенд не проверяет

- Настоящий клиент Telegram: жесты, системные кнопки, GPS телефона.
- Настоящую доставку сообщений ботов: текст, кнопки и посты стенд видит в заглушке.
- Голос звонка (Cloudflare Realtime): звонок звонит, но не соединяется. Значения Realtime на стенде ненастоящие и никуда не ведут (G33).

Это владелец смотрит на телефоне перед запуском, а не после каждой цели.
