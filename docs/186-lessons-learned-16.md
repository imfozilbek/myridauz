### №289. Имя метода из запроса как ключ обычного объекта

- **Что случилось:** G82, 15.10.2026: CodeQL на PR #238 нашёл серьёзную находку в заглушке стенда `telegram-looks.mjs`: `reads[method]?.(…)`, где `method` берётся из адреса запроса.
- **Причина:** у обычного объекта есть свои методы (`constructor`, `toString`); такое имя вызвало бы чужую функцию. Я не считал заглушку стенда кодом, который читает чужой ввод.
- **Следствие:** вреда нет, это локальный стенд; два лишних круга CI: CodeQL помечает и вызов функции из `Map` по такому имени. Исправлено: имя только сравнивается с известными, тест на оба имени.
- **Урок:** имя из запроса (адрес, тело, заголовок) никогда не выбирает функцию для вызова: только сравнение с известными именами. Данные по такому ключу ищу в `Map`. В любом коде, тестовые заглушки тоже.

### №292. В цепочке команд оказался `git checkout -p`

### №298. Чужая ветка уронила проверку секретов во всех PR

- **Что случилось:** 15.10.2026, PR #245: проверка `secrets` (gitleaks) нашла «ключ». В моём коммите ключа не было. Находка в ветке G69 `goal/g69-growth-loops`: `"later": "Keyinroq",`, а следом ключ перевода `"phrase.join.0"`.
- **Причина:** правило `generic-api-key` ищет слово «key»; узбекские «keyin», «keyinroq», «keyingi» его содержат. CI проверяет историю всех веток, поэтому ложная тревога в одной ветке краснит все PR и `main`.
- **Следствие:** ключа нет, утечки нет. G69 закрыла свой случай отпечатком в `.gitleaksignore`, я в тот же час: исключением в `.gitleaks.toml`. Два решения одной находки.
- **Урок:** узбекские тексты дают ложные «ключи». Исключение узкое: только правило `generic-api-key` и только «keyin» (`.gitleaks.toml`), настоящий ключ проверка ловит дальше (проверено); отпечаток одного коммита больше не нужен. Красный `secrets`: сначала gitleaks локально по всем веткам (`--log-opts=--all`), потом выводы.
