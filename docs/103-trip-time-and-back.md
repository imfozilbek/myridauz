# 103. Дата и время на одном экране, «Назад», правила создания поездки

> **Кратко:** решения владельца 03.10.2026, пункты 1 … 7. Дата и время выбираются на одном экране. «Назад» внутри мастера ведёт на шаг назад, после законченного действия ведёт на главную. Поездка не раньше чем через час, водитель должен успеть доехать до новой поездки, не больше 3 поездок одновременно. Календарь и часы показывают только разрешённое. Цель G38 (`goals/G38-trip-time.md`). Изменение поездки (пункты 8 … 10): `104`, цель G39.

## Решения владельца 03.10.2026

| № | Правило |
|---|---|
| 1 | Дата и время на одном экране во всех мастерах: поездка, предложение водителя, заявка попутчика |
| 2 | «Назад» внутри мастера всегда ведёт на шаг назад. После законченного действия (поездка создана, бронь, заявка, предложение отправлены) «Назад» ведёт на главную. Проверяются все мастера трёх Mini App |
| 3 | Водитель должен успеть доехать: см. «Правило времени» ниже. Фиксированных 4 часов нет |

| 7 | Не больше 3 активных поездок (было 5). Принятое предложение тоже поездка. Старые поездки не трогаем |

## Правило времени (пункт 3)

После поездки A → B водитель в B. Новая поездка C → D разрешена, если:

> отъезд C → D ≥ конец A → B + дорога B → C + время на сбор людей

- То же в обе стороны: после новой поездки водитель успевает к следующей уже созданной.
- Обратная поездка B → A и любая поездка из B: дорога 0.
- Конец поездки уже считается (`endsAt`). Дорогу между районами даёт справочник мест (`48`).
- Время на сбор = длина новой поездки × коэффициент, с границами.

| Число | Предложение Claude | Решение владельца |
|---|---|---|
| Коэффициент сбора | 0,5 | ждёт |
| Сбор не меньше | 1 час | ждёт |
| Сбор не больше | 3 часа | ждёт |
| Отъезд не раньше | 1 час | ✅ 1 час |
| Время по умолчанию | 08:00 | ✅ 08:00 |
| Активных поездок | 3 | ✅ 3 |

Все числа лежат в одном месте: конфиг бренда (`22`), не в коде.

## Пример

| После Toshkent → Samarqand (4 часа) | Дорога | Сбор | Можно ехать |
|---|---|---|---|
| Samarqand → Toshkent | 0 | 2 часа | через 6 часов после отъезда первой |
| Samarqand → Buxoro | 0 | ×0,5 от длины | конец + сбор |
| Jizzax → Toshkent | Samarqand → Jizzax | ×0,5 от длины | конец + дорога + сбор |

## «Назад»: причина и переходы (G38)

**Причина.** При смене шага старый шаг отпускал кнопку, код сразу слал Telegram «спрятать», новый шаг сразу «показать». На телефоне кнопка после этого иногда не отвечала. Тесты не видели: заглушка Telegram нажимала даже скрытую кнопку (урок №110). Теперь кнопка прячется, только если после смены шага её никто не взял (`screen/back-stack.ts`).

| Мастер | Шаги вперёд | «Назад» внутри | После законченного действия |
|---|---|---|---|
| Новая поездка (водитель) | маршрут → способ → день и время → места → цена → женщина → комментарий → проверка | на шаг назад, ответ сохранён | «Safar eʼlon qilindi»: на главную |
| Предложение на заявку (водитель) | день и время (день заявки) → цена → проверка | на шаг назад | «Taklif yuborildi»: на главную |
| Подтверждение брони (водитель) | бронь → подтверждение | на шаг назад | «Joy tasdiqlandi»: на главную |
| Заявка попутчика | маршрут → день → способ → посадка → высадка → цена → проверка | на шаг назад | «Soʻrov qoldirildi»: на главную |
| Бронь попутчика | способ → посадка → высадка → проверка | на шаг назад | «Soʻrov yuborildi»: на главную |
| Принятое предложение (попутчик) | предложение → принять | на шаг назад | «Joyingiz tasdiqlandi»: на главную |
| Жалоба, отзыв | форма → отправлено | к поездке | «Shikoyatingiz yuborildi», «Rahmat»: на главную |
| Заявка водителя | машина → цвет → номер → места → фото → проверка | на шаг назад | статус заявки, «Назад» на главную (было) |

«На главную» даёт `flow/home-context.ts`: главный экран приложения передаёт путь домой каждому разделу.

## Риски

- Новые правила на сервере ломают старые сценарии стенда и e2e (урок №107): время сценариев сдвинуть сразу.
- Правило «Назад» трогает все мастера: каждый закрыть тестом вперёд и назад.
