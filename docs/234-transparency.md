# 234. Полная прозрачность: путь людей по источнику, версии Telegram и платформе (G99)

> **Кратко:** решение владельца 13.11.2026: видеть, откуда пришёл каждый поток людей, на каком шаге он застревает и где Mini App не работает у старых и сторонних клиентов Telegram. Считаем **людей**, а не события и не сессии. Источник: **первое касание** человека (`116`). Аналитик получает файл CSV без личных данных. Ничего платного.

## T1. Что было до G99

| Что | Было | Чего не хватало |
|---|---|---|
| Шаги попутчика | `screen_open`, `way_step` (from, to), `trip_search` (found, empty), `trip_open`, `booking_step` (requested, confirmed), `boarded` (`29`) | Считались по сессиям; подтверждение и поездка видны не у всех |
| Шаги водителя | `screen_open`, `driver_application_step` (submitted), `driver_approved` (сервер), `trip_step` (published), `booking_step` (confirmed) | Первая бронь и законченная поездка водителя не считались |
| Источник | Метка `via` и вид ссылки `source` только на первом экране сессии; первое касание в D1 `user_arrivals` (`116`) | События после первого экрана не знали источник; повторный вход «direct» терял источник человека |
| Версия Telegram и платформа | Строка `client` («android 8.0 chrome 120») на первом экране сессии и при падении | У остальных событий и ошибок их нет: нельзя разрезать путь и ошибки |
| Люди | Только `sessionId` | Один человек в 5 сессиях считался 5 раз |
| Выгрузка | Нет | Аналитик не мог посчитать сам |

## Как сделано

- **Каждое событие Mini App** (`packages/contracts/src/path-stamp.ts`) несёт: `who` (публичный id человека; до регистрации id сессии), `entry` (метка первого касания человека из профиля; до регистрации метка сессии), `tg` (версия Telegram WebApp, «8.0»), `platform` (android, ios, tdesktop, weba, webk, macos, unknown). Analytics Engine: `blob12` … `blob15`.
- **Профиль** (`/me`) отдаёт метку первого касания `entry` из `user_arrivals`.
- **Шаги, которые видит только сервер**, берутся из D1 (`stats/infrastructure/d1-paths.ts`), по разу на человека, с первым касанием из `user_arrivals`: `approved`, `first_booking`, `trip_done` водителя; `confirmed`, `rode` попутчика. Версия Telegram у них: первого касания.
- **Люди:** `count(DISTINCT blob15)`. Человек, который заходил с двух версий Telegram, в разрезе версий виден в обеих строках.
- **Версии:** ниже 7.0, 7.x, 8.x и выше; «unknown» отдельно (сторонние клиенты обычно не называют платформу).

## Экран и файл (T5, T6)

- «Statistika» → «Yoʻl manbalari», «Telegram versiyalari», «Telegram ilovalari»: строка = люди и ошибки среза; нажатие открывает путь попутчика и водителя. Период: 24 soat, 7 kun, **30 kun** (новый), Hammasi. Ответ `GET /admin/stats/paths`, кэш 10 минут.
- «Tahlilchi uchun fayl» (только владелец): админ бот присылает два файла CSV: `paths-<период>.csv` (строка на человека: id, источник, метка, версия, группа версии, платформа, время каждого шага, UTC) и `errors-<период>.csv` (ошибки по источнику, версии и платформе). Без телефона, имени и Telegram ID.
- Ошибки среза: падения экранов и отказы запросов, без ошибок сети телефона.

## Бюджет (T7)

- Analytics Engine: 2 запроса на период раз в 10 минут (кэш), до 20 000 строк. Ничего платного.
- D1: один запрос по `driver_applications`, `bookings`, `trips` с объединением; при росте броней нужен индекс по `confirmed_at` и `boarded_at` (`117`, находка 16).
